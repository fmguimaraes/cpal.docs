**Method.** Five parallel auditors ran the static pass (tokens and theming, shell and
navigation, components, live tracking and map, history / pilotage / auth pages). Their
86 raw findings were deduplicated to 49, regraded where needed, and the doubtful ones
re-checked against the cited files. The runtime pass (crawl, screenshots, computed
colors) was **not run** in this audit: evidence is `file:line`, and contrast ratios are
computed from token values. The next audit adds screenshots in `shots/`.

## 1. Summary

- Conforming pages: **0/9 (0%)**. No previous audit.
- Findings: **9 Major-layout**, **32 Major-UI**, 8 Minor (49 total, from 86 raw).
- Kit gaps: 10 (§4); the kit itself now exists in the reference, but several items are
  coupled to the reference's mock data or miss app-specific behavior.
- Top three issues:
  1. There is no kit and no guideline lint in the app: every control is raw HTML
     styled with about 190 inline `style` props (F-10).
  2. The production CSP `img-src 'self' data: blob:` blocks every OpenStreetMap tile,
     so both maps render without a basemap in production builds (F-18).
  3. Below 768 px the sidebar hides every nav link and offers no drawer: there is no
     navigation on a phone (F-3).

### Major — layout

#### F-1 — Shell repeated per route, no layout route

- **Grade:** Major-layout
- **Where:** all shell routes; `src/App.tsx:36-75`; `src/chrome/AppChrome.tsx`
